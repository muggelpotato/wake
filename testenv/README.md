Fully automatic prod test env: when `run/plugins/wake/config.yml` has `database.type: mariadb`

| Service  | Address           | Purpose                                                                |
|----------|-------------------|------------------------------------------------------------------------|
| velocity | `localhost:25577` | **Join here.**                                                         |
| primary  | `localhost:25565` | `runServer` instance on the host (proxy-only while mariadb mode is on) |

Switch backends in-game with `/server backend2` and `/server primary`

## Headless testing
- **`python testenv/drills_obu.py --encoding`** the bytes `features/obu/protocol` writes, judged against the ids, framing, vanilla defaults and per-release id ceilings in `OBUSOURCE/OpenBoatUtils` — the ceilings read at its release tags, so the clone needs them — plus the algebra a removal and a struck status line share: what a selector reaches, what it takes and what a layer above only shadows. A probe compiled into the package prints each packet as hex (no server; needs `./gradlew compileJava` first). Without `--encoding` it also runs the command surface: every argument type parses, refuses, stores and displays, and a value the wire cannot carry never reaches the database
- **`python testenv/drills_obu_commands.py`** the fork every branch of `features/obu/commands` turns on: who owns an operation — a player owns a sandbox under their own id, a console addresses one by the key the table holds, an entity is neither — drilled exhaustively from the console side with the player side grafted straight into the table, every share code the import door has to refuse without leaving a half-made sandbox behind, what folding leaves in the table against what the cache says it holds, and that every setting the definition enum carries has a node of its own under `/wakeobu` and under `-clear` (needs a server)
- **`python testenv/drills_clients.py`** what `features/obu/clients` decides before anything else runs: the version handshake in every framing the mod has shipped — the current one built from `OBUSOURCE`'s own `VERSION`/`UNSTABLE`, and the flagless one every build before 0.5.0 sent — plus truncated, mis-framed and fuzzed payloads and the transaction reply the mod sends down the same channel, then the latch the verdict lands in, including eight handshakes racing on eight threads (no server; needs `./gradlew compileJava` first)
- **`python testenv/drills_join.py`** what a client is told on join, driven by a fake one that speaks the protocol itself: the handshake written the way `OpenBoatUtilsClient` writes it and sent where that build sends it — in the configuration phase, in play, or both at once — for the floor build, one below it, one the mod marks broken, the top of the table and one past it, each judged on what comes back down the stream (the console line, the outdated/ahead/refused line, whether a context went out at all, whether a refused build is left in game) plus the `update-nag` switch, the client-wide flags a switch and an import each owe a client already connected, and a quiet console behind all ten joins. `--config-delay` holds the configuration phase open the way registries and packs do, which is where a verdict answered before the join is lost. Speaks protocol 767, so it needs `./gradlew run1.21` **in offline mode**: `WAKE_RUN=testenv/matrix/1.21 python testenv/drills_join.py --port 25585`
- **`python testenv/drills_delivery.py`** what a boat is actually running: the pin in its container and the spelling it lands in, one written behind Wake's back, temporary overrides added, cleared, reset and replaced by a context, a removal narrowed to one per-block setting and one block of it while the rest stand, an impulse that is delivered but never stored, eviction when the boat leaves and when its chunk unloads under it (both drilled by giving the replacement the same UUID), a module cycle, the sweep over pinned boats behind a context delete, a sandbox publish and the name collision it refuses, a reload and an import, the protected contexts and the listing they appear in, what an empty store seeds, the names the import door has to refuse, every spelling of the keep window and a real purge sweep, and every `-settings` switch judged by the row it lands in rather than by the reply it gives (either backend)
- **`python testenv/drills_geometry.py`** the swept collision math at the root of `core/`: the segment-vs-box test, the block range it scans, the legs a tick's path is cut into, the tick clock (no server — compiles a probe against `build/classes`, so `./gradlew compileJava` first)
- **`python testenv/drills.py`** operational drills against primary: boot, five reloads in a row, and the outage/journal/replay cycle. Add `--sync` for the cross-server drill (needs mariadb mode). Add `--lifecycle` for the plugin lifecycle — a burst of writes into a `stop` over RCON, then two servers of its own booted straight from the jar, one whose database never answers and one whose state schema this build cannot read, to watch `onDisable` run against a half-built plugin. It stops the running server, so run it last and `./gradlew runServer` again afterwards (needs a current `./gradlew shadowJar`)
- **`python testenv/drills_database.py`** the `/wake database` admin surface and the outage journal's rough edges (either backend)
- **`python testenv/drills_core.py`** the core module's own commands: the switches and where they land, the boats `/wake killemptyboats` takes and the one it leaves alone (a mob aboard), the boat the auto-kill switch takes when a rider steps out and the one it waits on, the order a reload answers in (either backend)
- **`python testenv/drills_drydock.py`** the drydock commands: what `/dd boostpad add` stores and hands back, adding a block that already has a pad, the order the listing comes out in, a row stored under a key no command would have written, the early-out switches and where they land, and the pad flag on the export round trip (either backend)
- **`python testenv/drills_module.py`** the module lifecycle: config toggles, the module no toggle reaches, repeated off/on cycles, the hot listener a feature claims from the framework, an enable that throws, seeding (including the decision an outage postpones), the state prefix an export sweeps, the service seam (either backend)
- **`python testenv/drills_text.py`** the language file: every key the code asks for and every key the file carries, the palette and placeholders its header documents, and what a reload does to a file that is edited, broken or missing (either backend; the first half needs no server)
- **`python testenv/drills_changelog.py`** cross-server cache propagation over the sync bus: both directions, concurrent writes, bursts, a bus that is down at boot or killed mid-session, unusable sync settings (needs mariadb mode)
- **`./gradlew checkVersions --continue`** one `JavaCompile` per claimed version against that version's own `paper-api`, so an API added after 1.21 that would throw `NoSuchMethodError` on a server predating it is a compile error here. Exhaustive over every call Wake makes, ~8s for all fourteen, no server and no download. `--continue` is what makes it report every version rather than stopping at the first
- **`./gradlew run1.21`** … **`./gradlew run26.2`** a real server of any claimed version with this build's jar — one task per row of the `claimed` map, named for the version it boots, each on the JVM that version needs and keeping its own world and database under `testenv/matrix/<version>`. The first boot writes what run-paper does not: an accepted EULA, a peaceful creative flat world on the **standard port** so plain `localhost` reaches it, RCON on **25585**, and the two movement thresholds a boat at racing speed trips. It never writes over them again, so an edit in the run directory stands. Two servers cannot run at once, because the second one to want 25565 refuses to start
- **`python testenv/drills_versions.py`** the one thing neither of those can see: the `claimed` map is hand-written, because Gradle needs it at configuration time. This asks Paper which versions exist and fails if the map has fallen behind, or if a row is pinned to a `paper-api` that is not its own — which compiles green while checking one version twice and another never. It also reads the drills, because a path spelled out from the repository root ignores `WAKE_RUN` and drives whatever is in `run/`. Needs the network; no server, no build, no arguments
- Primary has RCON enabled (`localhost:25575`, password `wake-dev`) so console commands can be driven from
  scripts; a claimed version's server answers the same way on `25585`, and every path a drill reads — log,
  journal, database, config, exports — follows `WAKE_RUN`:
  `WAKE_RUN=testenv/matrix/1.21.3 python testenv/drills_drydock.py --port 25585`
- Paper2 answers to `docker exec wake-testenv-paper2-1 rcon-cli <cmd>`
- Outage drills: `docker stop wake-testenv-mariadb-1`, change configs (they journal to `run/plugins/wake/outage-journal.jsonl`), `docker start wake-testenv-mariadb-1` and watch the replay within ~5s.

## Notes
- Needs a populated run/ directory for server.properties etc. (run once with sqlite then with mariadb)
- MariaDB data and the paper2 world survive teardown. Removed plugins can linger in the paper2 volume; wipe everything with `docker compose -f testenv/docker-compose.yml down -v`
- If the gradle task is killed hard (Ctrl+C) the finalizer may not run and the stack stays up. The next `runServer` reuses it, or run `./gradlew testEnvDown` manually
- Port 3306 must be free
